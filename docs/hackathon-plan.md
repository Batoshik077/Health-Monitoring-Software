# План на хакатон

Цель — к 10-му часу сквозной поток «симулятор → аналитика → экран», с 34-го часа новые функции не добавляем.

## Объём работ

- **Обязательно:** симулятор (мок-данные), экран «Моё здоровье», ежедневная самопроверка (опросник и симптомы), правила и тревоги, **протоколы действий по тревогам**, обзор экипажа, живые графики, пульт сценариев.
- **Желательно:** личная норма (z-score), индекс готовности, журнал тренировок и оценка потери костной массы, доза радиации, Mission Control с задержкой и обрывом связи.
- **Если останется время:** ИИ-ассистент, который объясняет тревогу и отвечает на вопросы по протоколу; голосовая озвучка.
- **Не делаем:** реальное железо, авторизацию, облачный деплой, микросервисы.

## Роли

| Роль | Зона ответственности |
|---|---|
| Backend | FastAPI, симулятор, правила, тревоги, протоколы, WebSocket, симулятор канала |
| Frontend | Экраны астронавта, экипажа и Земли, графики, анимации тревог |
| Data / «медик» | Реалистичные сигналы, пороги, тексты протоколов, научные обоснования, источники |
| Pitch / дизайн / PM | Макеты, слайды, видео, сценарий демо, контроль времени |

## Таймлайн на 48 часов

| Часы | Что делаем | Контрольная точка |
|---|---|---|
| 0–2 | Договариваемся об API и формате событий, репозиторий, макет | Все знают свой фронт работ |
| 2–10 | Симулятор → API → WebSocket; каркас React с одним графиком | Цифры бегут на экране |
| 10–20 | Правила, тревоги, протоколы, «Моё здоровье», карточки экипажа | Работает сценарий «гипоксия» с протоколом |
| 20–24 | Сон | — |
| 24–34 | Самопроверка, Mission Control, задержка связи, пульт, z-score, готовность | Работают все сценарии |
| 34–40 | Полировка интерфейса, звук, дополнительная фича | Новые функции больше не добавляем |
| 40–46 | Слайды, видео, README, три репетиции | Демо укладывается во время |
| 46–48 | Резерв, сдача | Отправлено заранее |

Если хакатон длится 24 часа, время делим пополам и убираем всё «желательное».

## Сценарий демо (3 минуты)

1. Экипаж «зелёный», миссия на Марс, задержка связи 12 мин. Показываем «Моё здоровье» инженера.
2. На пульте — «гипоксия»: SpO₂ падает, через 30 с у инженера CRITICAL со звуком.
3. Астронавт открывает тревогу, видит причину и протокол, отмечает шаги; через 2 минуты SpO₂ перепроверяется и восстанавливается.
4. Ускоряем время: Земля видит тревогу только через 12 минут, когда астронавт уже справился сам.
5. Сценарий «усталость»: 5 ночей по 5 часов, падает готовность, появляется совет и сигнал медику.
6. Личная норма: пульс 85 в норме для всех, но не для инженера-спортсмена с пульсом в покое 52.

## Структура питча

1. **Проблема (30 с):** «Когда у астронавта на Марсе падает кислород, врач на Земле узнает об этом через 20 минут».
2. **Решение (20 с):** астронавт сам видит, что происходит, и знает, что делать.
3. **Живое демо (2 мин).**
4. **Архитектура (30 с):** одна схема и путь к продакшену.
5. **Влияние (30 с):** Artemis, Марс, а также Антарктида, подлодки, удалённые районы.

- Каждый сценарий вызывает нужную тревогу.
